# 03 · 微信文件与图片：能取到什么，取不到什么

这一章把话说清楚，因为这是本项目最容易被误解的部分。

## 一句话结论

- **文件**：能取，完整的原始文件，和聊天里收到的一模一样。
- **图片**：只能取到微信自己另外存的**明文缓存版本**（缩略图 / 收藏高清图 / 迁移图）。
  聊天里直接发送的原图是**加密**的，离线解不开，本项目不碰。

## 微信 PC 端把数据放在哪

程序会自动定位，不用手填。定位顺序：注册表里读自定义路径 → 各盘根目录扫 → 用户目录。
支持微信 4.x 和 3.x 两种布局：

```
微信 4.x
<数据目录>/xwechat_files/<wxid>/
├── msg/file/YYYY-MM/             ← 聊天收发的文件（带真实文件名）
├── msg/attach/                   ← 聊天图片的加密 .dat（V2，AES 全文件加密）
├── cache/YYYY-MM/Message/<会话hash>/Thumb/   ← 明文缩略图
└── business/favorite/temp/NoteCache/          ← 收藏的高清图

微信 3.x
<数据目录>/WeChat Files/<wxid>/FileStorage/
├── File/YYYY-MM/
├── Image/ ...
└── Cache/ ...
```

会话目录名 = **`md5(会话 wxid)`**，所以可以精确定位：

```
文件传输助手 = md5("filehelper") = 9e20f478899dc29eb19741386f9343c8
```

这就是为什么「转发到文件传输助手 → 手机上直接在那个会话里选」这条路能走得通。

## 文件：完整、可靠

`msg/file/YYYY-MM/` 下的文件就是原始文件，改名后缀都能直接用。
程序扫描后是**复制**到自己的工作区再打印，绝不移动、修改、删除微信的原始数据。

支持按时间过滤（"收件箱模式"）：只列出某个时间点之后新收到的文件，
时间点存在手机浏览器本地，下次打开接着看新东西，不用在几百个文件里翻。

## 图片：三个明文来源

| 来源 | 位置 | 特点 |
| --- | --- | --- |
| `chat` | 缓存 Thumb 目录 | 覆盖面最广，收到消息自动生成；清晰度看原图大小 |
| `favorite` | 收藏 NoteCache | 质量最好的一批，通常是高清 png |
| `migrate` | 迁移产物 | 明文 png |

每张图都会算一个**清晰度评级**并给出建议纸张，手机上直接能看到：

| 标签 | 含义 | 建议 |
| --- | --- | --- |
| 清晰 | A4 满幅也够用 | 随便打 |
| 一般 | 放大到 A4 会略软 | 打 A5/A6/4R 更合适 |
| 偏软 | 只有几百像素 | 小尺寸照片或别打 |

这个标签是拿图片实际像素和 A4 在 300dpi 下需要的像素（约 2480×3508）比出来的，
不是拍脑袋定的。扫 300 张缩略图，大概只有不到 30 张够 A4 满幅清晰——这是缓存本身的限制，不是程序的问题。

**想要高清图怎么办**：在微信里把图片**"以文件形式"发送**（或者直接发原文件），
它就会落在 `msg/file/` 下，和文件一样完整可取。

## 为什么不解密原图

聊天里直接发的图片，微信 4.x 在 `msg/attach/` 下存的是 V2 格式的 `.dat`：
**整个文件 AES 加密，没有明文区，密钥只在微信进程内存里**。

要解开只有两条路：

1. 注入微信进程、扫描内存拿密钥 —— 这是外挂/木马的行为，而且违反微信用户协议；
2. 让微信自己导出 —— 也就是"另存为"或"以文件形式转发"。

本项目只走第 2 条。所以请别提"能不能直接把聊天原图打印出来"的需求，答案是不能，
而且这个限制不会因为版本更新而改变（除非微信主动开放接口）。

## 使用前提

- 电脑版微信**必须保持登录并运行**（否则不会有新文件落盘）
- 首次使用建议在手机上点一次刷新，等扫描完成（几百个文件约 1-2 秒）
- 扫描结果有 12 秒缓存，避免每次刷新都全盘 stat

## 隐私边界

- 只读、只复制，不写不删不上传
- 不读聊天数据库（不解析任何消息内容）
- 不注入微信进程
- 所有文件只在局域网内流转，服务不联网
